# ثنايا | Thanaya Medical — متجر المستلزمات الطبية وطب الأسنان

> **الحالة:** مشروع تطوير محلي قيد الإنجاز، **غير جاهز للنشر العام** بعد. هذا المستودع نسخة إعادة تصميم مستقلة عن المشروع الأصلي.  
> **آخر تحديث توثيقي:** 2026-10-20. الميزات أدناه تخص فرع `feature/medical-batch-expiry-guard`؛ فروع العمل متسلسلة وما زالت تحتاج مراجعة قبل دمجها في `main`.

## فكرة المشروع

متجر إلكتروني للمستلزمات الطبية ومستلزمات طب الأسنان في العراق: واجهة للمشتري، ونظام إدارة للمنتجات والطلبات والمخزون والإعدادات.

**التقنيات:** Next.js 16 وReact 19 وTailwind CSS للواجهة، Express وTypeScript للباك إند، Prisma 5 وSQLite محلياً.

## ما أُنجز حتى الآن

### 1. واجهة المشتري والطلبات — منجزة مبدئياً
- الرئيسية والتصنيفات والبحث والمنتجات وتفاصيل المنتج والسلة وإتمام الطلب.
- إعادة حساب الأسعار والمخزون من الباك إند قبل الطلب، وحماية من الطلبات المتزامنة التي تحاول شراء آخر قطعة.
- منع الخصم المكرر عند إعادة محاولة الطلب، وعرض طلبات المستخدم المسجل في صفحة الحساب.
- متابعة حالة الطلب، وإرجاع المخزون عند الإلغاء/الإرجاع بالشروط المنفذة، مع سجل حركات.

### 2. كتالوج المنتجات والمخزون — منجز برمجياً، مع اختبار عملي نهائي متبقٍ
- صور متعددة للمنتج (حتى 5 إضافية) ومواصفات منظَّمة (حتى 12 بنداً).
- رمز SKU اختياري وفريد، وموديل وقياس ووحدات بيع متعددة.
- إدارة الكميات مع توثيق كل حركة.
- تتبّع اختياري للتشغيلات وتاريخ الصلاحية للمنتجات الجديدة بمخزون صفر بلا سجل سابق.
- خصم مخزون التشغيلات بطريقة **الأقرب انتهاءً أولاً (FEFO)**، واستبعاد المنتهي من المتاح للبيع، وإرجاع القطع إلى نفس التشغيلات في الإلغاء/الإرجاع.
- **قيد مقصود:** المنتج القديم المرتبط بمخزون أو مبيعات لا يمكن تحويله مباشرة إلى نظام التشغيلات؛ حمايةً لتاريخ المخزون.

### 3. لوحة الإدارة والميزات الداعمة
- إدارة المنتجات والتصنيفات والمستخدمين والصلاحيات والطلبات، والبحث/التصفية في الإدارة.
- كوبونات وعروض، وإعدادات المتجر والتوصيل التي يتحكم بها المالك.
- إشعارات داخل الموقع حسب الحساب، وتقارير عن الطلبات والمبيعات والمخزون.
- رفع صور المنتجات والتحقق من نوع الملف وحجمه.

## ما بقي قبل الاكتمال

1. **المرحلة الثانية — إغلاق الفحص:** تجربة شراء حقيقية مضبوطة على منتج تجريبي ذي تشغيلة، ثم التأكد من الخصم والإرجاع وظهور الأرقام الصحيحة في لوحة الإدارة.
2. **المرحلة الثالثة — حساب الزبون:** عناوين محفوظة، تحسين تتبع الطلبات وإعادة الطلب، وإكمال تجربة الملف الشخصي. توجد صفحة حساب وطلبات حالياً لكنها ليست كل المرحلة.
3. **المرحلة الرابعة:** الفواتير والمدفوعات والمرتجعات الجزئية والتصدير (مثل Excel).
4. **المرحلة الخامسة:** إكمال الإشعارات والتواصل حسب احتياج المتجر.
5. **المرحلة السادسة:** إعادة صقل التصميم وتجربة المستخدم UX/UI والموبايل.
6. **المرحلة السابعة:** اختبارات أمنية وتشغيلية ونهاية-إلى-نهاية، ثم **النشر آخر خطوة** فقط.

## تشغيل الموقع الموجود على جهاز Mac

افتح نافذتين Terminal داخل مجلد المشروع:

**Terminal 1 — الباك إند**
```bash
cd ~/Documents/thanaya-dental-redesign/backend
npm run dev
```

**Terminal 2 — الفرونت إند**
```bash
cd ~/Documents/thanaya-dental-redesign/frontend
npm run dev
```

- المتجر: `http://localhost:3000`
- إدارة المنتجات: `http://localhost:3000/admin/products`
- الباك إند: `http://localhost:4000`

إذا فشل تحميل المنتجات، تحقق من تشغيل الباك إند. لا تخلط بين `npm run dev` و`npm run build`: الأول للتشغيل المحلي والثاني لفحص/بناء الكود.

### الإعداد على جهاز جديد فقط

بعد تثبيت Node.js وnpm، ثبّت الحزم في مجلدي `backend` و`frontend` باستخدام `npm ci`. جهّز `backend/.env` من `backend/.env.example` وضع `DATABASE_URL` و`JWT_SECRET` بمفاتيح صحيحة. إنشاء قاعدة جديدة إجراء مستقل يُنفذ فقط عند الإعداد لأول مرة، وليس على نسخة المستخدم المحفوظة.

**لا تنفّذ `npm run db:push` أو أي Reset على قاعدة بيانات فيها طلبات أو مخزون إلا بعد نسخة احتياطية موثقة ومراجعة التغييرات والتحذيرات.**

### فحوصات الكود

من `backend`:
```bash
npm run test:orders
```
هذا الاختبار يستخدم قاعدة بيانات **مؤقتة معزولة**، ولا يلمس `backend/prisma/dev.db`.

من `frontend`:
```bash
npm run build
```

**آخر نتائج أُبلغ عنها في التطوير المحلي:** نجاح 15 اختبار تكامل للطلبات والمخزون والتشغيلات، وبناء 25 مساراً في الواجهة بلا أخطاء TypeScript. هذه نتائج اختبارات محددة، **وليست شهادة جاهزية للنشر العام**.

## سلامة البيانات والخصوصية

**لا تُرفع إلى GitHub:** قاعدة البيانات الفعلية `backend/prisma/dev.db`، ملف الأسرار `backend/.env`، والصور المرفوعة في `backend/uploads`. هذا يعني أن تنزيل المستودع على جهاز آخر **لا** ينقل المنتجات أو الطلبات أو الصور المحلية تلقائياً.

احتفظ بنسخ احتياطية خاصة من قاعدة البيانات والصور. لا تستبدل أو تحذف قاعدة البيانات المحلية أو الأسرار عند تبديل الفروع، ولا تعرض بيانات الزبائن الحقيقية أثناء التصوير أو العرض.
