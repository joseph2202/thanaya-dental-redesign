# حدود البحث وفلاتر الكتالوج

البحث العام يشمل الاسم والوصف والماركة وSKU والموديل والقسم، ويقتصر على published=true. category وbrand فلتران مطابقان؛ البحث الجزئي في القسم عبر search. الكلفة وسجل الدفعات لا يخرجان للعامة، وavailableStock يستثني المنتهي.

| الحقل | العقد |
| --- | --- |
| search | نص مفرد، حتى 100 حرف |
| category / brand | نص مفرد حتى 90 / 120 حرفاً |
| minPrice / maxPrice | أرقام IQD عشرية صحيحة من 0 إلى 1,000,000,000؛ فراغ يعني لا حد |
| النطاق | min ≤ max إذا حضرا |
| sort | فارغ للأحدث، أو price-asc / price-desc / name؛ id ترتيب ثانوي ثابت |
| inStock في صفحة المنتجات | 1 أو غائب/فارغ؛ يعتمد availableStock، لا stock المنتهي |

API ترفض القيمة المكررة أو غير الصالحة 400 مع رسالة، ولا تسقط الفلتر إلى بحث عام. /products تعرض رابط استعادة عربي قبل تمرير string[] إلى واجهة تتوقع string؛ لا 500 بسبب URL. القارئ نفسه يستعمل في نموذج الفلاتر، مع تحقق مستقل في API.

## التحقق
backend/tests/catalog.integration.cjs ينشئ SQLite ومجلد uploads خاصين داخل OS temp ثم ينظفهما. فحوصه 22: البحث بالقسم وبقية الحقول، الجمع والحدود والترتيب، تكلفة خاصة وتوفر منتهي، تكرار كل فلتر، سعر علمي/hex/سالب/كسري/أكبر من الحد، نطاق مقلوب، sort=__proto__، طول النصوص، والفراغ. 13 حالة فشلت قبل الإصلاح؛ نجحت 22 بعده مع بناء Backend. تشغيله: RUST_LOG=info npm run test:catalog على Node 22 (لا قاعدة حقيقية).

Frontend production build نجح (35 مساراً). frontend/tests/catalog-browser.cjs يضيف Chrome فعلياً لبحث Dental (موجود في القسم فقط)، جمع السعر/الماركة/التوفر والترتيب، خطأ نطاق السعر في نموذج الهاتف، منتج غير متوفر لا يضاف، ثم روابط مكررة/غير صالحة واستعادة الكتالوج. النتيجة الفعلية تنتظر CI للدفعة 17.

لا مخطط جديد أو تعديل بيانات قديمة. مرحلة الأداء وWebKit وتباين تأكيد الطلب والحماية من فساد localStorage ما زالت منفصلة وغير مكتملة.
