# THANAYA Dual Theme · Signature rollout candidate

## قرار التصميم
بعد تجربة مستخدم ثنايا للمعاينة الداكنة والإعجاب بها، طلب اعتماد **الداكن والفاتح بنفس التصميم** وتحسين القياسات وإعادة عبارة البنر:

> احتياجات عيادتك، أسهل مع ثنايا.

## التغييرات المنفذة على هذا الفرع
- **حُسّن مختبر /theme-preview**: مسافات أكثر توازناً وبنر جديد بعبارة ثنايا المطلوبة، بنفس التركيب بالوضعين الداكن والفاتح.
- **أُضيف مفتاح داكن/فاتح في Header ولوحة الإدارة**؛ آخر اختيار محفوظ في `localStorage` عند السماح به، وموحد بين الصفحات في نفس المتصفح، مع مزامنة التبويبات الأخرى.
- **الوضع الداكن افتراضي على هذا الفرع فقط**؛ الألوان الأصلية الفاتحة ما زالت قابلة للاختيار، وكل الصفحات تستخدم وظائفها الأصلية. لم نبدّل عناوين APIs أو نماذج طلبات أو سلة حقيقية بمكونات الـMock الخاصة بمختبر التصميم.
- طبقة `site-dual-theme.css` لتلوين الخلفيات والبطاقات وعناصر البحث والكتالوج والسلة ولوحة الإدارة والنوافذ حسب الوضع المختار. تراعي status/error colors وتباين النصوص.
- **البنر الحقيقي في الصفحة الرئيسية** ما زال يستعمل عنوان `bannerTitle` الذي يمكن للمالك تخصيصه من الإعدادات؛ القيمة الافتراضية هي العبارة المطلوبة. هذا الفرع يحسن عرض البنر بالوضعين دون أن يمحو تخصيص المالك المخزن.
- تحسين أسماء класّات CSS فقط لتسهيل التحكم في خلفيات الـHeader/Footer/الإدارة والبطاقات بالثيمين، ولا تغيير بخدمات المخزون أو تسعير الطلبات.

## حدّ الاختبار والموافقة
- **الفرع منفصل، ولم تُدمج التغييرات إلى فرع التصميم الأساسي أو `main`**؛ التفعيل محلياً يكون فقط عندما يختار المستخدم تبديل الفرع.
- **فحوصات GitHub ناجحة:** Run `39956169738` نجح في بروفة الترحيل الآمنة واختبار التفعيل على SQLite مؤقتة واختبارات الطلبات/المرتجعات المعزولة و`Next.js npm run build` مع TypeScript. لا تعادل هذه الفحوصات الموافقة البصرية على جميع صفحات المتجر.
- اختبار الألوان حتماً يحتاج معاينة حقيقية على الموبايل والديسكتوب لمراقبة التباين والقراءة واختبارات إدخال البيانات، خصوصاً صفحات `/checkout`, `/admin/products`, `/admin/orders`, وmodal النوافذ.
- **لا ندّعي أن كل صفحة مصقولة نهائياً قبل المعاينة البصرية، ولا إطلاق عام/دمج بدون قرار صاحب المتجر.**

## حماية البيانات
لا API POST/PUT/PATCH/DELETE في كود الثيم، ولا تغييرات في `backend`, `Prisma`, SQLite أو جداول الاسترداد المالي. مفتاح الوضع محفوظ فقط في التخزين المحلي للمتصفح إذا كان متاحاً. لا يتضمن صور منتجات وهمية ولا بيانات مبالغ مختلقة.

## الخطوة التالية بعد الموافقة البصرية
تدقيق contrast عبر الموبايل الحقيقي، نماذج الخطأ والتحميل، وتجربة checkout حقيقية دون إرسال طلب، ثم تحسين المكوّنات المتبقية قبل إصدار نسخة مرشحة للإطلاق.
