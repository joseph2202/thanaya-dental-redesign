# مراجعة رحلة الشراء — بيانات صناعية فقط

دفعة 16 تربط تسميات الاسم والهاتف والمحافظة والعنوان والكوبون بحقولها، وتضيف autocomplete مناسباً. الهاتف يظل 11 رقماً يبدأ بـ07 كما يقبله السيرفر؛ أزيل العرض المتعارض +964 ووُضع مثال مطابق. لا تغيير لتنسيق البيانات المحفوظة أو تحقق السيرفر.

ملخص الطلب يحمل اسماً واضحاً للقارئ الآلي وaria-busy. عند غياب إعداد أجور توصيل نهائية يظهر «المجموع قبل أجور التوصيل» والتنبيه المناسب؛ أثناء التحميل أو الخطأ يكون المجموع تقديرياً. لا تُحوّل أجور مجهولة إلى وعد بشحن مجاني.

## السيناريو الجديد
`frontend/tests/checkout-browser.cjs` يُستدعى من fullstack-session-proxy.cjs بعد فحوص ERP والمالية والمعرض. ينشئ contexts منفصلة، وحساب متسوق صناعي، ويعدل إعدادات fixture باستخدام صلاحية مالكها وCSRF الفعليين. لا حساب تاجر أو شبكة دفع.

| الحالة | التحقق المتوقع داخل fixture |
| --- | --- |
| توصيل غير مضبوط | المجموع لا يدعي شمول أجور التوصيل، والهاتف بتعليمات تطابق الحقل |
| سعر محفوظ قديم 40,000 ثم سعر سيرفر 45,000 | التأكيد يتطلب الموافقة على السعر الجديد |
| نفاد المخزون بعد فتح Checkout | الفحص النهائي يمنع الإنشاء ولا يستهلك كوبوناً أو يحفظ محاولة مبكرة |
| إعادة توفر البضاعة | تحديث الصفحة يعيد مراجعة السعر والتوصيل؛ لا تعديل صامت لطلب قديم |
| خصم 5,000 وشحن البصرة 5,000 | subtotal=45,000، total=45,000، وكلها من السيرفر |
| ضغط مزدوج وضياع رد POST بعد نجاحه | طلب واحد، قطعة واحدة مخصومة، استعمال كوبون واحد، واسترجاع requestId بدلاً من شراء ثانٍ |
| COD جديد | سجل التحصيل صفر وحالة الطلب pending؛ التسليم والدفع مستقلان |
| النجاح | صفحة التأكيد، سلة ومحاولة فارغتان، وعرض هاتف بلا overflow |

البناء وsyntax ينفذان محلياً؛ السيناريو يحتاج Chrome في CI ولا يعد ناجحاً حتى تظهر النتيجة. اختبار fullstack ينشئ SQLite ومرفقات ومالكين صناعيين في OS temp، ويمتنع عن استعمال بورت API إذا كان مشغولاً؛ لا يكتب في dev.db الحقيقي.

## ثبات بيئة CI
يُثبت playwright-core في مسار أدوات مستقل تحت RUNNER_TEMP، ويضاف عبر NODE_PATH. لا ينفذ npm install إضافية داخل frontend بعد npm ci/build؛ بذلك تبقى اعتماديات التطبيق التي فحصت وبنيت من lockfile نفسها أثناء تشغيل المتصفح. أداة المتصفح ليست اعتماداً إنتاجياً أو تغييراً في lockfile.
