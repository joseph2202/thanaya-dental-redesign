## تم تطويره في فرع feature/business-documents-export (بانتظار فحوصات الماك)

### 1. ملخّص طلب قابل للطباعة / PDF
- صفحة `/order/invoice?id=...` تطبع مستند A4 عربي RTL بتفاصيل العميل والعنوان وبنود الأسعار والكميات المحفوظة والسعر والتوصيل والخصم.
- يمكن للموظف المخوّل فتحه من إدارة الطلبات، وللزبون من تفاصيل طلبه؛ الخادم لا يكشف طلب شخص آخر.
- زر «طباعة / حفظ PDF» يستخدم نافذة طباعة المتصفح، والزبون يختار **Save as PDF**. ليس هناك توليد PDF على السيرفر.
- **تحذير محاسبي:** هذه وثيقة *ملخّص طلب* وليست إيصال قبض أو فاتورة ضريبية أو إثبات دفع عند الاستلام.
- **قيد معروف:** اسم المنتج يُقرأ من اسمه الحالي؛ سعر الوحدة والكمية محفوظان وقت الطلب.

### 4. تصدير Excel حقيقي
- `GET /api/exports/orders?range=7|30|90|all`، أوراق «الطلبات» و«بنود الطلبات».
- `GET /api/exports/inventory`، أوراق «المنتجات والمخزون» و«التشغيلات والصلاحية».
- `.xlsx` حقيقي بأوراق متعددة وHeaders مُنسَّقة وعرض RTL، وليس CSV أُعيدت تسميته.
- النسخة الأولية تستخدم مكتبة XLSX بسيطة داخل الباك إند بدون تنزيل حزم جديدة؛ القيم النصية تُكتب كـinlineStr، لا تُنفذ أي صيغ خلايا مدخلة من الزبائن.
- التصدير مقصور على owner/admin فقط؛ يشمل حقولاً شخصية وحساسة لا يجوز إرسالها للعلن.
- حد التصدير 10 آلاف منتج أو طلب، وإلا تعود رسالة تطلب تضييق الفترة. لا تغيير في قاعدة البيانات.

## الميزات المتفق عليها التالية — غير منجزة بعد

### 2. تكاليف الشراء وصافي الربح
- أولاً تحديد طريقة التكلفة: تشغيلات جديدة = تكلفة لكل تشغيلة؛ المنتجات القديمة = تكلفة مرجعية فقط.
- **لا تدّعي أرباحاً تاريخية** من معلومات تكلفة لم تكن محفوظة عند الشراء.
- تصميم snapshots للتكلفة عند البيع، مع قواعد سعر الشراء والعمولات والمصاريف والتسويات.
- تحتاج schema وتعامل محاسبي آمن ونسخة احتياطية قبل أي تعديل.

### 3. المرتجعات الجزئية
- تسمح بإرجاع عدد محدد من بنود الطلب بعد التسليم، مع سجل جزئي **idempotent** لا يتكرر عند ضغط الزر مرتين.
- إرجاع المخزون إلى **نفس lot** المسجّل في طلب البيع إن كان المنتج يتتبع التشغيلات.
- معالجة المبالغ المستردة تختلف عن رجوع المخزون، وتتطلب حالة تسوية ولا نفترض رد أموال غير موثّق.
- لا تُطبّق من دون الاختبارات المالية والمخزنية المعزولة.

### 5. تنبيهات قرب انتهاء الصلاحية
- مستويات 30/60/90 يوماً مع استثناء الدُفعات ذات المخزون صفر.
- مخزون منتهي يُعرض بتنبيه مستقل ولا يُحتسب متاحاً للبيع.
- مبدئياً لوحة الإدارة قبل التنبيهات الخارجية.

### 6. عروض مرتبطة بمنتجات حقيقية
- صفحة `/offers` تتحقق من كود/تواريخ/حدّ عروض المبيعات التي تُعدّ فعالة بالفعل؛ لا تظهر عروض وهمية.
- لاحقاً تخفيضات أسعار على منتجات مختارة مع كشف سعر الأساس والتاريخ، يجب حفظ snapshot عند الطلب.

### 7. صقل الموبايل والواجهة
- فحص 390px / 768px / 1440px لصفحات الرئيسية، المنتجات، السلة، الدفع، الحساب، الإدارة، الفاتورة، التقارير.
- إصلاح تمرير أفقي ونصوص مقصوصة ومربعات غير متوازنة؛ مراجعة إتاحة العناصر بأصابع اليد.

## مؤجل حسب رغبة المستخدم
- نظام المندوبين والشفتات وواتساب وتأكيد الاستلام، حتى يُحسم سير التوصيل.
- اختبارات الإطلاق النهائية والنشر العام؛ **لكن اختبارات التغييرات الجديدة ووحدات سلامة المخزون إلزامية**.

## طريقة اختبار هذه الدفعة

بدون `db:push` لأن الفواتير والتصدير لا يضيفان حقولاً لقاعدة البيانات:
1. `cd backend && npm run test:orders` — يتوقع 19 اختباراً بقاعدة SQLite مؤقتة.
2. `cd ../frontend && npm run build`.
3. شغّل الخادمين وشاهد رابط «طباعة / حفظ PDF» بصفحة تفاصيل طلب حقيقي *من غير تغيير حالته*.
4. بحساب المالك، نزّل «تصدير كل الطلبات Excel» و«تصدير المخزون Excel»، وتأكد أن الأوراق تحتوي بيانات متسقة مع المخزون الفعلي.
5. انتبه لخصوصية أسماء الزبائن وأرقامهم وعناوينهم داخل ملفات Excel قبل مشاركتها.

الفرع يظل Draft لحين فحص المالك المحلي والفتح الفعلي داخل Excel/Numbers.
