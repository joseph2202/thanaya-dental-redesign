# إبطال الجلسة بعد تسجيل الخروج

## السلوك
تسجيل الخروج الناجح صار يسجل SHA-256 للتوكن في RevokedSession قبل مسح Cookie/CSRF. كل API محمية تمر بحارس بعد Cookie bridge وقبل routers؛ يعاد فحص السجل كل طلب بلا cache سلبية. يعيد استخدام نفس credential بعد الخروج 401، سواء Cookie أو Bearer، ويستمر الرفض بعد restart. تسجيل دخول آخر مستقل لا يخرج تلقائياً؛ كل login له jti عشوائية حتى في الثانية نفسها. الصلاحيات تبقى من دور User الحقيقي، كما في الاختبارات السابقة.

التوكن القديم بلا jti قابل للإبطال أيضاً، ولا تسجل JWT أو CSRF أو بيانات بطاقة في السجل. الأرقام/المخزون/الطلبات/المال لا تتغير. السجلات المنتهية تنظف داخل transaction الخروج؛ credential قديمة بلا exp تحفظ بعيداً ولا يعيد التنظيف تفعيلها. التوكن الموقعة ذات nbf مستقبلية تسجل كذلك؛ لا يقبلها الحارس قبل وقتها.

إذا تعذر قراءة السجل فالجلسة المحمية تفشل 503، ولا يستمر الوصول بافتراض نجاح القراءة. عند تعذر حفظ الخروج لا تمسح cookies ولا يدعي السيرفر نجاح الخروج؛ الواجهة الحالية تعرض الخطأ وتسمح بإعادة المحاولة. الدخول/التسجيل يفحص توفر السجل أولاً، فلا يصدر cookies أو يخلق حساباً جزئياً إذا كان غائباً. الكتالوج العام بلا credentials يبقى متاحاً.

Express يقبل اختلاف حالة حروف المسار وشرطة أخيرة افتراضياً؛ التطبيع في الحارس وترويسات الخصوصية يمنع تجاوزه عبر /API/AUTH/me أو logout/. التوقيع HS256 وCSRF والأصول الموثوقة باقية. إشعار محاكي الدفع الموقع مستقل عن مصادقة المستخدم ويظل تحت عقد HMAC الخاص به.

## إضافة المخطط — ليست مفعلة على المتجر الحقيقي
جدول RevokedSession جديد: tokenHash مفتاح فريد، userId داخلي، expiresAt وcreatedAt، وفهرس expiry. لا FK يجعل حذف حساب يعيد تفعيل credential، ولا نسخ تاريخ أو تغيير صفوف User/Order/Inventory. **لا تشغّل db push على قاعدة Mac.** الكود يحتاج هذا الجدول الصحيح قبل استخدامه على قاعدة قديمة؛ غيابه يعيد 503 بدل السماح بجلسات غير قابلة للإبطال.

backend/scripts/rehearse_session_revocation.py يقبل --source صريحة، يقرأها mode=ro ويختبر الإضافة في clone مؤقتة فقط؛ لا apply أو activation mode. يتحقق من الشكل/الفهرس/المفتاح/defaults وعدم تغيير صفوف المصدر أو WAL، ولا يختلق revocations قديمة. 8 فحوص بروفة ناجحة، بينها existing journal/صفوف محفوظة، schema غير مكتملة، فهرس مفقود، constraint غير متوقع، symlink/file مفقود، وWAL bytes. لا تفعيل حقيقي هنا. ما زال يلزم مسار activation محمي بنسخة احتياطية متحققة وموافقة تشغيل منفصلة، مثل إضافات ERP05/06 وOrderStatusEvent المعلقة.

## التحقق
اختبار API الجديد فشل على المصدر القديم: replay بعد logout أعاد 200 بدلاً من 401. بعد الإصلاح نجحت 6 مجموعات تكامل على SQLite صناعية:
- إعادة Cookie/Bearer عبر مسارات حساب/طلبات/عناوين/إدارة، مع CSRF والأصل الموثوق والكتالوج العام.
- jti مستقلة لجهازين، إبطال جلسة واحدة، تكرار logout وrestart API.
- credential قديمة بلا jti/exp، وnbf مستقبلية؛ hashes فقط في التخزين.
- تطبيع case/trailing slash وترويسات no-store؛ اختباره كشف تجاوز case أولاً ثم مرّ بعد الإصلاح.
- غياب الجدول يفشل 503 بلا cookies أو حساب جزئي، ثم تعافٍ بعد استعادته.
- تنظيف hashes منتهية وعدم اختلاق مال/مخزون.

نجحت auth.integration.cjs وroles.integration.cjs وبناء Backend بعد التغيير. Next fullstack smoke صار يعيد إرسال Cookie المنسوخة بعد logout ويتوقع 401 عبر rewrite، بدلاً من الاكتفاء بإثبات إزالة Cookie من المتصفح. النتيجة الكاملة تنتظر CI لهذه الدفعة؛ لا ادعاء نجاح المتصفح قبلها.

## المتبقي
لا تعرض هذه الدفعة قائمة أجهزة/جلسات ولا زر خروج من كل الأجهزة، ولا سياسة تلقائية جديدة عند تغيير password/role. تغيير الدور يظل يطبق صلاحيات DB الحالية (اختبار role القديم محفوظ). هذه توسعات لاحقة، إضافة إلى guarded activation وWebKit/التشغيل. عند الرجوع لكود أقدم لا يعرف السجل يلزم تقييم تدوير مفتاح التوقيع حتى لا تتجاهل النسخة القديمة إبطالات محفوظة؛ لا تنفذ rollback أو تدوير أسرار حقيقية هنا.
