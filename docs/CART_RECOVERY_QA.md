# حماية السلة واستعادة بيانات المتصفح

JSON صالحة شكلياً مثل {} أو null كانت تدخل CartProvider ثم تكسر reduce/بحث المنتجات وتمنع استخدام المتجر. التخزين المحلي قد يرمي SecurityError أو QuotaExceededError أيضاً. صار cartState.ts يقرأ unknown بحد حجم 500,000 حرف، ويحتفظ فقط بصفوف صالحة وفريدة وحقول snapshot معروفة؛ 50 منتجاً وكمية 1–100. الصفوف الصحيحة لا تضيع مع صف تالف، والتكرار لا يجمع كميتين بصمت.

المخزون والسعر في localStorage لا يتحولان إلى حقيقة تجارية: يبقي القارئ snapshot القديمة (حتى سعر صفر أو مخزون قديم صفر)، وquote السيرفر يمنع الشراء الخاطئ ويعرض الأسعار الجديدة. لا حذف أو تسعير أو شراء في DB. القراءة والكتابة محميتان بـcatch؛ السلة تعمل بالذاكرة مع تنبيه للمستخدم عند الحجب. تحديث ref مع كل تغيير يمنع جمع أحداث إضافة على قراءة render قديمة، وتحديث الكمية لا يقبل كسراً أو أكثر من 100.

## التحقق المنفذ
Node 22: node --experimental-strip-types --test tests/cart-state.test.cjs؛ 9 فحوص نجحت: legacy، roots/JSON، صفوف تالفة، تكرار، كميات، هوية/سعر/مخزون، صفر/snapshot قديمة، optional غير آمن، وحدود الصفوف والحجم. بناء Next نجح (35 مساراً). لا اعتماديات إضافية أو lockfile جديد.

cart-recovery-browser.cjs يختبر DOM فعلياً على DB fullstack الصناعية: roots تالفة تصبح سلة فارغة قابلة للاستخدام مع تنبيه، احتفاظ بصف سليم دون دمج التكرار، سعر snapshot=1 مع عرض quote السيرفر الجديد، ثم Storage prototype يرمي للسلة فقط عند القراءة/الكتابة: تبقى الإضافة والانتقال للسلة وزيادة الكمية صالحة بلا pageerror. اجتاز CI #257 كما تسجل النتيجة أدناه.

لا مزامنة cross-tab ضمن هذه الدفعة؛ السلة خاصة بكل سياق واجهة وتظل أسعارها ومخزونها خاضعين للمراجعة من السيرفر. WebKit وفحوص وصولية شاملة ما زالت بالمصفوفة.
