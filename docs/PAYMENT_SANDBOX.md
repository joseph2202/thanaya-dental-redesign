# محاكي الدفع الدائم — Preview فقط

الدفعة 9 تربط adapter بملف SQLite مستقل `payment-sandbox.sqlite` في مجلد OS temp الخاص بالمعاينة. لا جدول يضاف لقاعدة المتجر، ولا حركة تكتب في OrderPaymentEvent، ولا حالة طلب أو مخزون تتغير من المحاكي. كلمة paid هنا حالة **تجريبية فقط**، لا قبض أو تسوية فعلية.

## الحواجز
- `NODE_ENV=production` يمنعه قطعاً حتى مع بقية الأعلام.
- يلزم `THANAYA_PREVIEW_ONLY=1` و`THANAYA_PAYMENT_SANDBOX=1` ومفتاح محاكي عشوائي مستقل 32 byte.
- root حقيقي تحت OS temp، باسم thanaya-preview-* وصلاحيات خاصة، وpreview.sqlite بالضبط بلا symlink. علامة خاصة يكتبها seed بعد نجاح إنشاء البيانات الصناعية تطابق المسار والجهاز/inode.
- ملف journal الموجود يجب أن يحمل application_id/version معروفين؛ لا يتبنى ملف SQLite آخر. الإعداد المعطل لا ينشئ ملفاً.
- هذه حماية من توجيه عرضي لقاعدة حقيقية؛ مدير نظام يزوّر الملفات والإعدادات عمداً خارج نموذج التهديد. لا تنسخ بيانات حقيقية إلى المعاينة.

`scripts/preview-local.sh` يولد العزل والمفتاح ويزيلهما عند Ctrl+C. لا يطبع مفتاح توقيع الدفع. requires Node >=22.13 للمحاكي (CI يستعمل 22.23)؛ لا تحمل مكتبة node:sqlite في المتجر العادي قبل اجتياز الحارس. [توثيق Node 22](https://nodejs.org/download/release/v22.13.0/docs/api/sqlite.html).

## API
كل المسارات `/api/payment-sandbox` خاصة وno-store. owner فقط باستثناء webhook الموقع. بقية الأدوار ترفض في السيرفر. Cookie CSRF باق لكل أزرار المالك.

| المسار | الوظيفة |
| --- | --- |
| GET / | حالة التوفر، آخر 20 محاولة وأرقام/مبالغ طلبات المعاينة، بلا معلومات اتصال |
| POST /intents | orderId/requestId فقط؛ يقرأ المبلغ والعملة من السيرفر |
| GET /intents/:reference | الدليل المحلي المحفوظ وإيصالات الأحداث |
| POST /intents/:reference/simulate | تحريك المزود الصناعي وإيصال إشعار أو إسقاطه عمداً |
| POST /intents/:reference/reconcile | استعلام من المزود واستعادة إشعار مفقود |
| POST /intents/:reference/refunds | مبلغ IQD ومعرّف ثابت؛ سقف تراكمي وCAS |
| POST /webhook | bytes أصلية بحد 8KiB وتوقيع حديث؛ لا يعتمد على Cookie أو ادعاء المتصفح |

قبل تطبيق webhook يقارن باستعلام المزود. إيصال الحدث فريد وhash للمحتوى الطبيعي بترتيب ثابت، وتحديث الحالة داخل transaction واحدة. لا raw body أو بيانات بطاقة. الدليل القديم/المكرر لا يرجع الحالة للخلف. فشل حفظ الإيصال يرجع الدليل المحلي؛ حالة المزود الخارجية تبقى ويمكن إصلاحها بالاستعلام، كما في بوابة حقيقية.

الحفظ دائم خلال حياة **نفس** المعاينة ويثبت بعد restart للـAPI؛ حذف مجلد المعاينة يحذفه عمداً. ليس سجل مدفوعات الإنتاج أو دفتر حسابات.

## التحقق الفعلي
`backend: npm run test:payment-sandbox` ينشئ بيانات صناعية، ويختبر restart/replay/التزامن/rollback/الصلاحيات والتوقيع وCSRF والتعطيل في production وحواجز الملفات. كما يقارن bytes قاعدة المتجر التجريبية وWAL قبل/بعد لضمان عدم تغيرها. فحوص auth وpreview الأصلية نجحت بعد الربط. لا تفعيل أو Migration على Mac.

الدفعة 10 تضيف PaymentSandboxPanel داخل طرق الدفع: للمالك فقط وعندما يؤكد السيرفر enabled. إنشاء محاولة ومراجعة المحفوظ، التفويض والفشل والإلغاء والدفع وضياع الإشعار والمطابقة والاسترداد. المفاتيح ثابتة عند إعادة محاولة نفس الطلب/المبلغ بعد خطأ شبكة. لا حقل لرقم بطاقة أو مفتاح. يوجد اختبار Chrome جديد عبر الواجهة ينتظر CI؛ بناء الواجهة ناجح.

واجهة Checkout النهائية تبقى COD فقط حتى تكتمل طبقة سجل الإنتاج ومزود تاجر فعلي واختباره والتصريح به.
