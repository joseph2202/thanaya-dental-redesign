# قراءة تأكيد الطلب — الثيمان والهاتف

صورة التأكيد من CI #251 كشفت عيباً بصرياً حقيقياً رغم صحة الشراء: text-ink الداكن صار #eefaff لكن bg-[#edf7fc] ظلت فاتحة، ويقارب تباين هذا الزوج 1.02:1 من قيم المصدر؛ لا تكفي مطابقة النص في الاختبار الوظيفي لاعتماد القراءة.

OrderExperience.module.css يحدد أزواج سطح/نص/نص ثانوي/نجاح/تنبيه/خطأ وروابط لكل صفحة الطلب وOrderProgress. لا توسيع لتخمين قوائم hex في theme العامة، ولا blur على المال أو النماذج. الهوية cyan والطلب وواجهاته المالية لا تتغير. زر cyan له نص ink داكن (بدل الأبيض ذي التباين 3.18:1)، و44px والتركيز الواضح.

## الفحص
order-experience-browser.cjs يُستدعى بعد رحلة شراء فعلية ناجحة وasserts الطلب/المخزون/الكوبون/التحصيل. يقرأ computed styles داخل main المرئية ويجمع خلفيات الأسلاف الشفافة ثم يقيس تباين النص المرئي: ≥4.5:1 للنص العادي، ≥3:1 للكبير. لا يدعي أنه تدقيق وصولية شامل أو بديل لـWebKit.

- dark/light و320/390/768px: النص، overflow، الإجمالي الدلالي، المرحلة الحالية، 44px وأثر لوحة المفاتيح.
- confirmed/shipped/delivered/cancelled/returned تعرض عبر fixtures استجابة GET فقط لتغطية لون المرحلة المكتملة/الآتية والحالات النهائية؛ لا تعدل الطلب أو مخزونه أو أمواله. يؤكد API في النهاية بقاء الطلب pending.
- forced-colors/reduced-motion تبقي المرحلة مسماة، وصورتا التأكيد dark/light محفوظتان للمراجعة.

بناء الواجهة نجح (35 مساراً)، وsyntax/diff ناجحة. CI #256 اعتمد فحص المتصفح وقرئت الصورتان كما تسجل النتيجة أدناه.

## النتيجة الفعلية
النتيجة المعتمدة: PR #74، 7a1d6f29، CI #256 ناجح. قياس المتصفح لكل dark/light/320/390/768 والحالات سجل min 4.67:1؛ صورتا الثيمين قُرئتا بعد الإصلاح.
