# ثنايا — فحص المتجر بعد تفعيل المرتجعات محلياً

**الهدف:** فحص عرض السلع وتسجيل المرتجعات الجزئية دون المساس بمبيعات أو مخزون حقيقي.

## أ. حماية البيانات (الخادمان متوقفان)
1. اسحب آخر الفرع، ثم نفّذ `python3 backend/scripts/safe_backup.py --check-only && python3 backend/scripts/safe_backup.py --backup`.
2. تأكد من `SQLite integrity: ok`، ووجود جدولَي `OrderReturn` و`OrderReturnLine` (القيمة `0` متوقعة)، وظهور `BACKUP VERIFIED`.
3. النسخة **الجديدة** تختلف عن النسخة التي أُنشئت قبل إضافة الجداول؛ احتفظ بالنسختين محلياً وبشكل خاص.
4. لا تعيد تشغيل `prisma db push`، ولا تدمج Pull Request #29 قبل إكمال الاختبارات.

## ب. فحص القراءة فقط
1. شغّل `(cd backend && npm run dev)` و`(cd frontend && npm run dev)` في نافذتي Terminal منفصلتين.
2. افتح `http://localhost:3000/admin/orders` بحساب مخوّل.
3. راجع الطلبات القديمة: يجب أن يظل عددها 7 قبل إنشاء أي طلب تجريبي، وأن تظهر أسماء السلع وكمياتها على بطاقات الطلبات بدون فتح الفاتورة.
4. فتح التفاصيل والفاتورة يجب أن يظهر أسعار وكميات الطلب القديمة كما كانت. للأوامر القديمة `productName=null` ويُستخدم اسم المنتج الحالي كبديل؛ **لا نزعم أن الاسم التاريخي موجود للطلبات القديمة**.
5. افتح `/account` بحساب الزبون وتحقق من ملخص أسماء المنتجات في بطاقات الطلب.

## ج. اختبار إنشاء طلب ومرتجع على منتج تجريبي حصراً
**لا تستخدم طلبات الزبائن القديمة أو المنتجات الفعلية لهذه الخطوات.**

1. أنشئ منتجاً اختبارياً واضح الاسم، ومخزونه التجريبي 5 أو أكثر، وسعره مثالياً 1,000 دينار. أو استخدم بيئة اختبارية مستقلة.
2. أنشئ طلباً تجريبياً جديداً من حساب زبون تجريبي لعدد 5 قطع، وتحقق من ظهور **اسم المنتج الفعلي وقت الشراء** والكمية وسعر الوحدة.
3. في لوحة الإدارة غيّر حالة الطلب التسلسلية إلى `confirmed` ثم `shipped` ثم `delivered`.
4. اضغط «استلام مرتجع جزئي»، اختر 2 قطعة، واكتب سبباً واضحاً، وأكّد الاستلام.
5. المتوقع: رجوع قطعتين فقط للمخزون التجريبي، ظهور «مرجع 2» بجانب المنتج وسجل السبب والتاريخ. الحالة تبقى `delivered` لأن 3 قطع لم ترجع بعد، ولا يتغير `Order.total`.
6. حدّث الصفحة؛ يجب أن يبقى عدد المرجع 2 (بدون تكرار). لا تضغط إرسال نفس المرتجع مرة ثانية عمداً على البيانات الحقيقية.
7. من «مرتجع» الكامل بعد الجزئي، يجب أن يرجع **الباقي 3 فقط**، ويتحول الطلب إلى `returned` ويصبح مجموع المرجع 5 لا 7.
8. إن كان المنتج يتتبع التشغيلات، اختَر رقم التشغيلة الحقيقي والكمية المستلمة لكل تشغيلة، وتأكد أنها ضمن التخصيص الأصلي للطلب.

## حدود هذه المرحلة
- المسار الحالي يعدّل **الرصيد المخزني فقط**؛ لا يُثبت أن المبلغ وصل أو رُدّ، ولا يعدّل إجمالي الطلب القديم.
- **البضاعة التالفة** أو غير الصالحة لإعادة البيع لا تُسجّل هنا؛ نحتاج نظام حجر وتلف منفصل.
- تقرير المبيعات الحالي لا يعكس تسويات نقدية للمرتجعات الجزئية؛ لا تستخدمه كصافي مبيعات بعد المرتجعات.
- النجاح في tests/build لا يغني عن معاينة شاشات الهاتف واختبار المسار عبر المتصفح.
