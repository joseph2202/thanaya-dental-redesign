# ثنايا — تفاصيل السلع المشتراة والمرتجعات الجزئية

> **فرع تطوير غير مفعل، غير منشور، ولم تُشغّل فحوصات Mac عليه بعد.**
> مهم: التغييرات تتضمن **Schema** جديداً في Prisma. لا تنفذ `db:push` على SQLite الحقيقية قبل نسخة احتياطية صحيحة وفحص الفقدان.

## ماذا كان موجوداً، وماذا تغير؟

- كان `OrderItem` يحفظ `productId` و`quantity` و`price` وقت الطلب؛ عرض اسم المنتج كان يعتمد على الاسم الحالي في جدول المنتجات.
- أُضيف `OrderItem.productName String?`: يتم ملؤه من اسم المنتج الذي يقرأه الخادم **في معاملة الشراء**. الاسم لا يأتي من مدخلات الزبون.
- الطلبات القديمة لا نخمن أسماءها التاريخية: إذا `productName` فارغ، تعرض الواجهة الاسم الحالي للمنتج الموجود.
- صار اسم كل سلعة وكميتها ظاهرَين مباشرة على بطاقة الطلب في لوحة الإدارة وصفحة «حسابي»، وفي تفاصيل الطلب/الطباعة/Excel يُفضل الاسم المحفوظ.

## استلام مرتجع جزئي للمنتجات المستلمة فعلياً

- واجهة إدارة الطلبات (owner/admin): زر «استلام مرتجع جزئي» للطلبات `delivered` فقط، مع إدخال كمية لكل بند والسبب.
- API محمي: `POST /api/orders/:id/returns`:
  `{requestId:UUIDv4, reason:"...", items:[{orderItemId,quantity,lots?:[{lotId,quantity}]}]}`.
- الإعادة بنفس `requestId` وبنفس البيانات تعيد الحدث الأصلي **بدون خصم/إضافة مخزون ثانية**. استعمال المفتاح نفسه لبيانات مختلفة يُرفض.
- `OrderReturn` و`OrderReturnLine` يسجلان التاريخ وهوية الموظف والسبب والكمية، وكل `lotId` أصلي عند وجود تشغيلات. لا نكتب على بنود الطلب الأصلية أو نغيّر سعر البيع التاريخي.
- تُحسب الكمية المتاحة للإرجاع لكل بند من مجموع `returnLines` السابقة. تُمنع الكميات السالبة أو الزائدة أو تكرار البند.
- إذا شملت عملية البيع أكثر من تشغيلة، يختار المسؤول **رقم التشغيلة الفعلي** للقطع المستلمة؛ لا يستنتجها النظام تلقائياً أو يخمّن تشغيلة.
- سجل المخزون وتحديث المنتج والتشغيلات والمرتجع في **معاملة واحدة**؛ حقل `Order.returnRevision` يوفّر كشف تنازع بين المرتجعات المتزامنة.
- إذا بقيت قطع لدى الزبون، تبقى حالة الطلب `delivered` ويظهر تاريخ الإرجاع الجزئي. إذا استُرجعت **كل القطع** يصير `returned`. زر «مرتجع» الكامل بعد مرتجع جزئي يعيد الباقي فقط عبر نفس النظام.
- يقرأ `OrderItemLot` ليعيد القطع فقط إلى التشغيلات التي خُصمت عند الطلب. القطع منتهية الصلاحية تعود إلى الرصيد الفيزيائي لتلك التشغيلة، لكن لا تدخل المعروض للبيع إن كانت منتهية حسب منطق FEFO السابق.

## فصل المخزون عن الحسابات

- **هذا استلام بضاعة قابلة لإعادة المخزون، وليس عملية ردّ مبلغ.**
- لا نخفض `Order.total` ولا نفترض أن الدفع عند الاستلام تم تحصيله أو استرداده. مبلغ مستحق للزبون يحتاج تحديد خصم القسيمة، التوصيل، التحصيل، وطريقة التسوية والموافقة عليها.
- منتجات تالفة/غير صالحة للبيع يجب عدم إعادة عرضها للبيع؛ يلزم مسار مستقل للحجر والإتلاف أو مرتجع بلا إعادة بيع قبل استخدام هذه العملية لتلك الحالات.
- تقرير «قيمة الطلبات المسلّمة» الحالي لا يحسم المرتجعات الجزئية مالياً. لا تستخدمه كصافي مبيعات أو أرباح بعد المرتجعات دون دفتر تسويات.

## فحوصات معزولة مطلوبة قبل أي تفعيل

على Mac، بعد الانتقال إلى هذا الفرع:
```bash
cd ~/Documents/thanaya-dental-redesign
git status -sb
git fetch origin
git switch --track origin/feature/partial-returns-order-item-snapshots
(cd backend && npm run test:orders) && (cd frontend && npm run build)
```
إذا الفرع المحلي موجود، استخدم `git switch feature/partial-returns-order-item-snapshots` بدلاً من `--track`. لا تنفذ switch مع تغييرات محلية غير محفوظة.

- يتوقع **23** اختباراً (20 سابقاً + 3 للاسم المحفوظ، التكرار والرفض، والمرتجعات الجزئية/الكاملة والمتزامنة والتشغيلات).
- الاختبارات تستخدم SQLite **مؤقتة** في `/tmp` وتنفذ `prisma db push` عليها فقط؛ لا تستخدم قاعدة البيانات الفعلية.
- إذا نجحت فحوصات Mac، راجع الواجهات وأمان الصلاحيات، واختبر المتصفح على 390px/768px/1440px.
- **قبل تطبيق Schema على بيانات حقيقية**: أوقف الخادمين، استخدم SQLite Online Backup API لقاعدة `backend/prisma/dev.db` واحفظ `backend/uploads` نسخة منفصلة، تحقق من `PRAGMA integrity_check` وأعداد المنتجات والطلبات والمخزون، ثم راجع خطة التطبيق وتحذيرات Prisma بعناية. أوقف عند أي `Reset` أو `Data loss` ولا توافق. استعد من نسخة احتياطية مجرَّبة فقط عند الحاجة.

## التفعيل والإطلاق

- هذه الدفعة لا تدمج نفسها في `main`، ولا ترحّل قاعدة البيانات ولا تنشر إلى الإنتاج.
- مستقبلاً: أضف سير موافقة مالية منفصل للتسويات النقدية والمرتجعات التالفة، وتقارير مبيعات صافية منضبطة مع الخصومات والتوصيل.
