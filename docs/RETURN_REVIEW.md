# مراجعة مالية المرتجعات — RC1

المسار GET /api/reports/return-review?range=30&page=1 للـowner/admin حسب دور DB الحالي. range إحدى 7/30/90/all، والصفحة عدد موجب حتى 99999، 20 سنداً في الصفحة بترتيب createdAt ثم id تنازلياً. query مكررة/مجهولة أو خارج النطاق ترفض 400، والصفحة التي زالت أو سجل متناقض 409، وتعطل DB يعيد 503 بلا أرقام بديلة. الرد private/no-store.

كل صف سند استلام OrderReturn حقيقي، والفترة تخص receivedAt لا تاريخ البيع؛ الطلب القديم الذي أعيد اليوم يدخل اليوم. receivedAt المستقبل لا يدخل. بند المنتج يستخدم اسم لقطة البيع، لا بيانات الزبون/عنوانه أو reason/notes أو أسعار التكلفة الحالية.

التكلفة التاريخية تستخدم OrderItemCostSnapshot الأصلية وOrderItemLot لتحديد cohort البيع. كمية snapshot يجب أن تغطي cohort الأصلية؛ تخصيص مفقود أو تكلفة NULL أو متعددة غير قابلة لتعيين القطعة تعني مجهولاً. الصفر موثق إن كان الصفر في الأصل، ولا يستبدل NULL بصفر. التكلفة هنا تكلفة بيع القطعة سابقاً؛ ليست قيمة بضاعة مستعادة ولا قيد عكس COGS. الحجر لا يزيد مخزون البيع.

currentOrderLedger يستخدم snapshot نفسها من paymentLedger مع توزيع خصم البضاعة بأعداد صحيحة، وvalidation الكميات والحركات. هذه أرقام **كل الطلب الحالية**؛ قد تتكرر في أكثر من سند، ولذلك لا يوجد مجموع لهذه الأرقام عبر الصفوف. grossSaleValueIqd قبل الخصم والشحن. refundableRemainingIqd سقف رد مسموح فقط، وليس التزاماً أو موافقة على دفع. الرد/التحصيل لا ينشآن من receipt أو status. لا يرد الشحن تلقائياً.

لا توجد حالة settlement معتمدة في المخطط الحالي؛ settlementRecorded=false وrequiresReview=true مقصودان لكل سند، حتى لو سُجل refund. لا ندعي أن كل السندات ديون ولا أنها مسواة. الطلبات القديمة بحالة returned بلا أي receipt تظهر بعدد منفصل لكل الفترات، لا يُخترع لها تاريخ/مبلغ أو بند. هذا تقرير مراجعة يقود إلى دفتر الطلب، وليس دفتر أستاذ أو قيد تسوية جديداً.

واجهة /admin/reports#return-review مرتبطة بلوحة التحكم و/​​admin/finance?orderId=ID. read-only فقط، مع تفاصيل البضاعة/التكلفة/الدفتر، pager، تحميل وخطأ/retry. إلغاء الطلبات المتأخرة ومطابقة range/page يمنعان عرض مبلغ من فترة تحت اختيار فترة أخرى. لا حساب تلقائي لصافي ربح أو ذمم من الطلبات المرتجعة؛ الاستبعاد المحافظ في التقارير الأخرى محفوظ.

فحص API صناعي: node backend/tests/return-review.integration.cjs بعد بناء Backend؛ يتضمن صلاحيات DB، خصوصية، وقت الحدث، تكلفة المنتج/lot الأصلية مقابل mutable cost، الحجر، نقص/غموض التكلفة، خصم دقيق، pagination، فساد الكميات/الدفتر، وbyte-identical DB/WAL لطلبات GET. driver private-preview-qa تشغل launcher الحقيقية ثم receipt محجوراً وتختبر الواجهة بالموبايل والتأخر/الخطأ وربط المالية.
