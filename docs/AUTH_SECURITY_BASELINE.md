# ثنايا — أول دفعة تأمين تسجيل الدخول (مراجعة/اختبار قبل الدمج)

تطوير مستقل على فرع `feature/auth-security-baseline`، مبني من `feature/private-remote-preview`. **لا تغييرات Prisma أو قاعدة بيانات**.

## التغييرات

- فحص بيانات التسجيل على الخادم: اسم 3–80 حرفاً، بريد صالح حتى 254، هاتف عراقي 11 رقماً يبدأ بـ07، كلمة مرور جديدة 8–128 حرفاً.
- تخزين البريد للحسابات الجديدة بصيغة صغيرة وبدون فراغات؛ معالجة خطأ Prisma `P2002` في تسجيل بريد مكرر بدون 500.
- تشفير كلمات مرور الحسابات الجديدة بــbcrypt (cost 12 بدلاً من 10). لا نغيّر تجزئة كلمات مرور الحسابات السابقة؛ تبقى صالحة.
- حدود محاولات بمخزن داخل ذاكرة العملية: 10 كلمات مرور خاطئة للبريد خلال 15 دقيقة، 120 طلب دخول إجمالاً لكل مصدر خلال 15 دقيقة، و30 تسجيل لكل مصدر خلال 15 دقيقة. بعد التجاوز ترجع HTTP 429 و`Retry-After`.
- معدل المحاولات بالمصدر يستخدم عنوان اتصال socket الموثوق بدلاً من الثقة بـ`X-Forwarded-For` من الزائر؛ قد يشترك زوار المعاينة عبر Next.js proxy بعنوان واحد. هذه إعدادات **محلية مؤقتة** ويجب إعادة تصميمها بمخزن موزع وIP موثوق خلف reverse proxy في الإنتاج.
- سياسة CORS غير عامة؛ تسمح محلياً بـ`localhost:3000` و`127.0.0.1:3000`، ويمكن إعداد مزيد من الأصول في `CORS_ALLOWED_ORIGINS` مفصولة بفواصل عند الحاجة. الاستدعاءات الحالية من الواجهة تستخدم `/api` بنفس الأصل.
- رؤوس أمان أساسية للـAPI: `nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy`; إخفاء `X-Powered-By`.
- ضبط وصف التسجيل في الواجهة مع شروط الخادم (8 أحرف و11 رقم للهاتف). لا تغييرات على المدفوعات أو المخزون.

## الاختبار المطلوب على Mac

قبل الانتقال للفرع، احفظ أي تعديلات محلية وافحص `git status -sb`. إذا كل شيء نظيف:

```bash
cd ~/Documents/thanaya-dental-redesign
git fetch origin
git switch --track origin/feature/auth-security-baseline
(cd backend && npm run test:auth) && (cd backend && npm run test:roles) && (cd backend && npm run test:orders) && (cd frontend && npm run build)
```

إذا سبق إنشاء الفرع المحلي: `git switch feature/auth-security-baseline` ثم `git pull --ff-only`.

**كل اختبارات backend المذكورة تستخدم قواعد SQLite مؤقتة ومعزولة** لا تشغّل `db:push` على `dev.db`.

بعد النجاح، جرب صفحة تسجيل الدخول بحسابك الأصلي وبصفحة الحسابات المسجّلة سابقاً. لا ترسل كلمات مرور أو JWTs أو ملفات `.env` بالمحادثة.

## قبل النشر الحقيقي

هذه حماية أولية وليست تدقيق أمان مكتمل: يلزم إعداد rate limiting موزّع بمصدر موثوق، تطبيق CSP وHTTPS وسياسات الأسرار/النسخ الاحتياطية، حماية التسجيل من الإساءة، سياسة جلسات مناسبة، تدقيق صلاحيات كامل، وآلية رصد/logging لا تسجّل بيانات سرية.
