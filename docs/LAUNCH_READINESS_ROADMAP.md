# THANAYA — مراجعة المتبقي قبل الإطلاق | 22 أكتوبر 2026

> هذا تقييم حالة **فرع التطوير الحالي** `feature/private-remote-preview`، وليس وعداً بأن المزايا كلها مجرّبة في الإنتاج. توجد سلسلة من Pull Requests مسودة غير مدمجة في `main`.

## الموجود فعلاً في الفرع
- متجر Next.js باللغة العربية، منتجات/تصنيفات/عروض/بحث وسلة وCheckout وصفحات حساب الزبون.
- Express + Prisma + SQLite محلي؛ الطلبات وحجز المخزون الآمن مع فحوصات شراء متزامن ومنع التكرار والتسعير على الخادم.
- حسابات وصلاحيات متعددة (owner/admin/inventory/sales/customer)؛ عناوين توصيل محفوظة؛ إشعارات؛ نظام توصيل للمحافظات.
- مخزون حركات وتشغيلات مع تواريخ صلاحية FEFO، سجل تكلفة شراء خاص للإدارة، إظهار وحفظ أسماء السلع المشتراة.
- إدارة الطلبات وحالاتها، مرتجعات جزئية/كلية تعيد المخزون **القابل للبيع** فقط، سجلها، وفواتير مطبوعة وتصدير XLSX وتقارير أساسية.
- النسخ الاحتياطي/فحص SQLite/الترحيل المجرب؛ أكد المستخدم نجاح فحوصات الشيفرة والـSchema المحلي وحفظ بياناته القديمة.
- معاينة عائلية مؤقتة عبر Cloudflare Quick Tunnel، مع دعم منفذ API والصور خلف عنوان واحد.

## ناقص قبل النشر — حسب الأولوية

### P0 — الحماية والتشغيل
- **تأمين المصادقة العامة:** `backend/src/routes/auth.ts` لا يظهر فيه حدّ للمحاولات أو سياسة تحقق مكتملة على مدخلات التسجيل والدخول؛ يلزم rate limiting/validation وسجلات آمنة، وفحوصات لهذه الحالات.
- **حصر CORS:** `backend/src/index.ts` يستخدم `app.use(cors())` مفتوحاً؛ يحتاج إعداد origins موثوقة للإنتاج، مع مراجعة رؤوس الحماية والـHTTPS.
- **بيئة تشغيل ثابتة:** لا نعتمد على Mac + Quick Tunnel + SQLite محلية لطلبات زبائن حقيقية. نحتاج استضافة للواجهة وAPI، قاعدة مدارة ودائمة مع خطة نقل البيانات، تخزين صور دائم، مراقبة أخطاء ونسخ احتياطي واستعادة مجرّبة.
- **مراجعة فروع GitHub:** PRs #21–#30 وما قبلها متسلسلة كـDraft ولا توجد موافقة نهائية أو دمج `main`. يلزم تنظيف/دمج متدرج بعد اختبارات مستقلة.
- **اختبارات end-to-end:** إنشاء الحساب، تسجيل الدخول، الصلاحيات، عروض ومخزون، إتمام الطلب، الدفع/التوصيل، تعديل الحالة، الإلغاء، المرتجعات، الإشعارات، تصدير، الاستعادة. اختبر على هاتف وشاشة صغيرة مع خدمة شبكة خارجية.

### P1 — إتمام العمليات التجارية
- **مرتجع تالف/حجر**: المسار الحالي يعيد المخزون القابل للبيع، ولا يصح استخدامه للتالف أو المفتوح غير الصالح للبيع.
- **تسويات مالية:** رد مبالغ موثّق، متابعة تحصيل الدفع عند الاستلام، التعامل مع خصومات القسائم والشحن، والتقارير المحاسبية الصافية؛ حالياً المرتجعات لا تعكس رد نقدي و`Order.total` تاريخي.
- **تكلفة البيع التاريخية:** التكلفة الحالية مرجعية؛ لا يمكن حساب صافي الربح الصحيح بدون تثبيت تكلفة البضاعة عند كل عملية بيع ومصاريف التشغيل.
- **مراجعة الإدارة وتجربة الزبون:** الرسائل، النوافذ، شاشة الهاتف، تفاصيل الفواتير، صور المنتجات، إدخال أسعار/وحدات البيع، أخطاء المزامنة.

### P2 — الأداء والتسويق
- **قياس سرعة صفحة ثنايا:** شغّل `scripts/check_preview_speed.py` للمقارنة بين الماك والـTunnel. يلزم اختبار متصفح حقيقي أيضاً.
- **تحسين تحميل الصور:** الواجهة تستخدم `<img>` في عدة مواضع والصور في `backend/uploads` حتى 5MB للصورة. راجع thumbnails/responsive dimensions وWebP قبل الإطلاق.
- **الخط العربي:** `frontend/src/app/layout.tsx` يستورد CSS من jsdelivr. اعتمد خطاً مستضافاً محلياً عبر `next/font/local` عند تجهيز ملفات خط مرخّصة كي نتجنب طلب CDN إضافياً؛ لا تتخلّص من هوية ثنايا دون قرار تصميمي.
- **الهوية والموثوقية/SEO:** دومين مملوك، عنوان ووصف مخصصان للصفحات، sitemap وrobots وبيانات منتجات، سياسات الطلب/الإرجاع والخصوصية، معلومات الدعم، إشعارات الطلب، وتحليلات اختيارية تحترم الخصوصية.
- **لا تقيس الأداء عن طريق TTFB فقط:** سرعة ظهور الصفحة والتفاعل تعتمد كذلك على JavaScript والصور والخطوط وأجهزة الزوار.
