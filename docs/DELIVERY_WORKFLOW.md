# نظام متابعة وتسليم الطلبات في ثنايا — قرار مبدئي

> **الحالة:** تصميم مرن إلى حين سؤال صاحب المتجر عن طريقة التوصيل. لا يعتمد على شركة بعينها ولا يفترض وجود مندوبين تابعين للمتجر.

## الآلية الحالية المعتمدة

| الحالة | متى تصير؟ | منو مسؤول عنها؟ |
|---|---|---|
| pending / قيد المعالجة | عند نجاح تأكيد الشراء | النظام تلقائياً |
| confirmed / تم التأكيد | بعد تدقيق الطلب والتواصل مع الزبون | موظف مخوّل (sales/admin/owner) |
| shipped / بالطريق | عند تسليم الطرد إلى المندوب أو شركة التوصيل | موظف مخوّل |
| delivered / تم التسليم | بعد وجود تأكيد فعلي بالاستلام | موظف مخوّل حالياً |
| cancelled / ملغي | قبل إرسال الطرد وفق قواعد الحالة | موظف مخوّل؛ يَرجع المخزون بالعملية ذاتها |
| returned / مرتجع | بعد تسليم الطلب ووفق قواعد الإرجاع | موظف مخوّل؛ يَرجع المخزون بالعملية ذاتها |

**قاعدة أساسية:** وصول الطلب لمرحلة "تم التسليم" ليس استنتاجاً من مرور الوقت ولا من فتح الزبون للموقع. لا يجوز تحويل الطلب تلقائياً من shipped إلى delivered بدون إثبات الاستلام.

## شنو يصير عند تغيير الحالة؟

1. الموظف يغيّر الحالة في لوحة الإدارة بحدود انتقالات الحالة المسموحة.
2. الباك إند يتحقق من صلاحيات الموظف، ويسجل الحالة الجديدة في قاعدة البيانات، ويرسل إشعاراً داخلياً إلى حساب الزبون.
3. صفحة تفاصيل الطلب تتحقق من آخر حالة **كل 30 ثانية** أثناء فتح الصفحة، وعند الرجوع للتبويب، ويظل زر التحديث اليدوي متاحاً.
4. صفحة «حسابي» تتحقق من ملخص الطلبات **كل دقيقة** أثناء فتح الصفحة، وعند الرجوع للتبويب.
5. إذا انقطع الاتصال، تبقى آخر حالة معروفة مع توضيح عدم تمكن التحديث. **هذا ليس اتصالاً لحظياً ولا تتبع GPS.**

## ليش اخترنا هالترتيب مؤقتاً؟

- يعمل مع مندوب خاص أو شركة خارجية أو استلام ذاتي بعد إضافة معلومات الخدمة المناسبة.
- لا يحتاج رقم شركة أو ربط API غير متاح.
- لا يغيّر بيانات الطلبات القديمة أو حقول المخزون، ويحافظ على صلاحيات إدارة الحالات السابقة.
- يسمح بإكمال تجربة الزبون الآن، وتأجيل تفاصيل المندوب وعنوان التسليم حتى نعرف عملية المتجر الحقيقية.

## قبل بناء مرحلة المندوب الفعلية: أسئلة لصاحب المتجر

1. هل الشحن بمندوبين تابعين للمحل أم بشركة توصيل أم الاثنين؟ ولأي محافظات؟
2. شلون يعرف المحل أن الزبون استلم الطرد؟ اتصال؟ رسالة شركة؟ تطبيق مندوب؟
3. شلون يتم التعامل مع محاولة توصيل فاشلة أو الزبون يرفض الاستلام؟ وشكد أجور التوصيل والمرتجع؟
4. منو مسموح له يعدّل حالات الطلب؟ مدير، موظف مبيعات، مندوب؟
5. هل تحتاج شركة التوصيل رقم تتبع أو اسم مندوب أو إثبات تسليم؟

## إضافات لاحقة بعد التحقق

- طريقتا توصيل مرنتان (مندوب متجر / شركة خارجية) وبيانات الشحنة/المرجع.
- صلاحيات المندوبين إن كانوا تابعين للمحل، أو تكامل شركة توصيل إذا توفر API رسمي.
- إثبات التسليم المناسب (توقيع/رمز لمرة واحدة **إذا توافق التشغيل مع الزبون**)، مع حماية الخصوصية وعدم افتراض أن مجرد ادخال كود كافٍ دون تدابير أمنية.
- سجل تدقيق مفصل بأوقات الانتقال والفاعل والأسباب، وحالات فشل التوصيل والمرتجعات الجزئية إذا احتاجها المتجر.
- إشعارات آنية/Push لاحقاً عند توفر المتطلبات، بدل فحص دوري لصفحات مفتوحة.

**مهم:** النسخة الحالية ليست جاهزة للنشر العام، ولا يجب تقديمها كمنظومة تتبع شحن لحظية.
