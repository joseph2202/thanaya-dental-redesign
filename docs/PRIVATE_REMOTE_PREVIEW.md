# ثنايا — معاينة المتجر من خارج الشبكة بدون استضافة

هذا دليل معاينة **مؤقتة ومحمية بالإيميل** لأحد أفراد العائلة أو مختبر، باستخدام Cloudflare Quick Tunnel على جهاز Mac. المتجر وقاعدة SQLite يبقيان على الماك، ولا ترفع الأكواد أو قاعدة البيانات إلى خادم استضافة.

> هذه بيئة مراجعة وليست نشر Production. استخدمها لفترة قصيرة ولأشخاص موثوقين فقط. تحتوي النسخة المحلية على حسابات وطلبات وصور؛ لا تستخدم رابطاً عاماً بدون تحقق بالبريد الإلكتروني. لا ترسل كلمة مرور المالك لأي زائر.

## تعديل البنية في هذا الفرع

- `frontend/src/lib/api.ts`: الواجهة أصبحت تطلب `/api/...` من نفس عنوان الصفحة، بدلاً من `http://localhost:4000/api`.
- `frontend/next.config.ts`: Next.js يعيد توجيه `/api/*` و`/uploads/*` إلى Express المحلي `127.0.0.1:4000` داخل الماك.
- روابط الصور القديمة `http://localhost:4000/uploads/*` تُعرض كـ `/uploads/*` (ضمن بيانات API وصورة المنتج)؛ لا حاجة لتعديل قيم قاعدة البيانات.
- لا تغيير في Prisma أو بيانات الزبائن أو الإعدادات السرية.

## 1. الفحص بعد سحب الفرع

```bash
cd ~/Documents/thanaya-dental-redesign
git status -sb
git fetch origin
git switch --track origin/feature/private-remote-preview
(cd backend && npm run test:orders) && (cd frontend && npm run build)
```

إذا كان الفرع المحلي موجوداً مسبقاً، استعمل `git switch feature/private-remote-preview` ثم `git pull --ff-only origin feature/private-remote-preview`. لا تنتقل قبل حفظ أي تعديلات محلية.

## 2. شغّل المتجر على الماك (ثلاث نوافذ Terminal)

- في الأولى:
```bash
cd ~/Documents/thanaya-dental-redesign/backend
npm run start
```
- في الثانية (بعد نجاح `npm run build`):
```bash
cd ~/Documents/thanaya-dental-redesign/frontend
npm run start
```
- تأكد أن `http://127.0.0.1:3000` يفتح، وأن `http://127.0.0.1:3000/api/health` يرجع `status: ok`، وأن صور المنتجات تظهر من رابط `/uploads/...` بدلاً من عنوان localhost:4000 على جهاز الزائر.

استخدام `npm run start` يعرض البناء الجاهز بدلاً من exposing أدوات تطوير Next.js.

## 3. أنشئ رابطاً مؤقتاً محمياً بالإيميل

على الماك، إذا Homebrew موجود:
```bash
brew install cloudflared
```
وإذا مثبت سابقاً: `brew upgrade cloudflared` لضمان دعم `--allowed-mail`.

افتح Terminal ثالثة بعد تشغيل 3000 و4000:
```bash
cloudflared tunnel --url http://127.0.0.1:3000 --allowed-mail 'brother@example.com'
```
**استبدل** `brother@example.com` بإيميل أخوك الحقيقي، ولا تشغّل Tunnel بلا `--allowed-mail`، لأن الرابط يصير متاحاً لأي أحد يعرفه. لاحظ أن حماية الإيميل تحتاج إصدار cloudflared حديثاً.

سيظهر رابط مؤقت من نمط `https://...trycloudflare.com` (اسم العنوان يتغير بكل تشغيل). أخوك يفتحه من جهازه على أي شبكة، ويستلم رمز تحقق لمرة واحدة على إيميله ثم يدخل المتجر. ليس محتاج حساب Cloudflare ولا برنامجاً بجهازه.

## 4. قواعد الأمان والتوقف

- لا تشارك رابط المعاينة علناً. لا تمنح حساب `owner/admin` لأي زائر، واستخدم مستخدم زبون اختباري إن احتجت اختبار تسجيل الدخول.
- لا تعمل معاملات حقيقية أو ترتيبات مالية في بيئة المعاينة؛ كل عملية شراء أو تسجيل حساب تعدّل قاعدة SQLite المحلية. إذا أردت تجربة الطلبات مع الزائر فالأفضل قاعدة بيانات اختبارية **منفصلة تماماً** عن بيانات المتجر.
- لكي تبقى الصفحة متاحة، يجب أن يظل **الماك صاحي ومتصل بالإنترنت**، والبـاك إند والفرونت إند والـTunnel شغّالين.
- للإغلاق: `Ctrl+C` بنافذة `cloudflared` ثم أوقف السيرفرين عند الانتهاء. الرابط يتوقف، ويتغيّر عند إنشاء رابط آخر.
- **لا تستخدم port forwarding على الراوتر، ولا تفتح بورت 4000 للعالم.**
- البروكسي داخل Next.js لا يعفي من مصادقة Express وأذونات المدير. بوابة البريد تحمي زيارة المعاينة لكنها ليست بديلاً عن الأمان والنشر الصحيح.
- انظر وثائق Cloudflare: https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/

## بديل خاص أكثر

يمكن استخدام Tailscale Serve، بحيث يحتاج الأخوَان إلى Tailscale (على الماك وجهاز الأخ)، وتكون الخدمة متاحة داخل شبكة Tailscale الخاصة بدل رابط عام. مناسب للمراجعات الدائمة بدون كشف موقع تجريبي على الإنترنت.
